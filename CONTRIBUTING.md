# Contributing

Read [agent instructions](AGENTS.md), [project status](docs/project/status.md), and the relevant design before changing behaviour. Contributions initially target CachyOS Niri. GitHub Issues and Pull Requests are the intended collaboration workflow; local [backlog](docs/project/backlog.md) is authoritative during bootstrap.

A substantial task describes title, objective, scope, acceptance criteria, dependencies, required tests, and documentation implications. Categories: Feature, Bug, Documentation, Refactor, Testing, Maintenance. Define intent first, implement a focused change, test it, and update documentation/status with the same logical commit.

Start with the [human developer guide](docs/development/getting-started.md). See [development environment](docs/development/environment.md), [conventions](docs/development/conventions.md), [testing](docs/development/testing.md), and [Git workflow](docs/development/git-workflow.md). Explain actual validation evidence and limitations in each PR. Never treat static boot checks as boot acceptance.
