# Shared branding

Status: **Implemented; Tested in isolated filesystems and native desktop deployment/reapplication/restoration**. Login/boot/splash activation remains separately unverified.

Own five exact filenames under `/usr/share/qubix/branding/`: `logo.svg`, `logo.png`, `banner.svg`, `LICENSE`, and `NOTICE`. The logo/banner are unmodified Apache-2.0 artwork from the pinned BlueBuild revision; an asset manifest records original paths and SHA-256 values. Preserve upstream distribution logos and identity files. This deployment initially requires CachyOS Niri although the artwork is platform-independent. No package or graphical-session dependency is needed to install inert artwork.

`branding.enabled` selects installation. The profile enables branding, Niri and shell; login/boot/splash are opt-in. `verify` remains inspection-only by default. A separate `verify --tags branding` selection checks already-installed files without writes. The supported-host/schema preflight must run for either selection.

Use copy tasks for fixed files with root ownership and mode 0644, namespace directories mode 0755, and post-copy SHA-256/type/mode checks. Reject symlinked namespace directories and managed files rather than following them outside the namespace. Preserve unlisted files. Reconcile these Managed files on reapplication; they are not existing distribution defaults. Check mode reports directory/copy proposals and explicitly skips post-install checks that cannot verify unwritten content. If the namespace is absent, file-copy preview is deferred until it exists and the proposed filenames are reported. Privilege escalation applies only to the installation block; read-only preflight and standalone verification stay unprivileged. Post-install verification runs inside the installation block.

Tests override internal role destination/ownership variables to an Ansible-created temporary directory and the current user; this is fixture isolation, not a public profile option. Production deployment uses the fixed system namespace. Tests passed: complete provenance/source checksums, zero file/directory changes on the second install, check-mode destination absent, damaged/missing/symlinked asset rejection, and unrelated files preserved. Setup/cleanup writes only an Ansible-created fixture directory under `.cache/tests/`; tests never invoke the system deployment playbook. See [asset provenance](../../assets/branding/README.md).

The shared file engine records original bytes/absence and restores only named files, preserving unlisted content. Disabling a component alone does not uninstall it. See [recovery](../user/restoration.md); whole-system rollback is outside scope.
